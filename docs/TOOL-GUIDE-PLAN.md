# 수업 도구 안내 블로그 시리즈 기획

정리일: 2026-11-02 · 상태: 9편 공개, `/tools` 허브 배포. 글은 lounge 저장소 `20261102131107_seed_landing_tool_guides.sql`로 넣었고 이후 수정은 `/blog/editor`에서 한다. 6장 확인 사항은 실제 윈도우 PC 검수 때 반영한다.

## 0. 목적과 확정 사항

「영상 제작을 위한 AI 활용」 4시간 수업([수업 계획서](https://docs.google.com/document/d/1ndgAq1aK-s9Xl0rxyxm02YCtOGZDfwu7Nv1MSOgy_YM/edit))에서 설치하고 사용하는 도구를 처음 접하는 사람도 이해할 수 있게 도구마다 블로그 글 한 편씩 한국어로 정리한다.

| 항목 | 결정 |
|---|---|
| 기본 운영체제 | **Windows**. 모든 설치·명령은 윈도우(PowerShell) 기준으로 쓰고, 맥은 글 끝 짧은 절로 덧붙인다 |
| Whisper | **공식 Python판**(`openai-whisper`). 그래서 Python 설치 글을 시리즈에 추가한다 |
| 글 형식 | **전체 공개 블로그 글**(`landing.blog_posts`, 갈래 `info`), 주소 `/blog/<slug>` |
| 모아 보기 | **`/tools`** 허브 페이지에서 시리즈 전체를 수업 순서대로 보여 준다 |
| 범위 | Node.js, FFmpeg, Git, Hyperframes, Whisper + Aside, Concat, kie.ai + 선행 도구 Python |
| 선행 도구 | 먼저 설치해야 할 프로그램이 있으면 **글 앞쪽에 그 글의 링크를 둔다** |

**독자:** 고객 지원·제품 안내·사내 교육을 맡은 기업 기술지원팀. 파일 저장·첨부와 웹 로그인은 할 수 있지만 터미널, 코딩, 영상 편집 경험은 없다고 가정한다. 검색으로 들어오는 일반 독자도 같은 수준으로 본다.

**원하는 반응:** "이게 왜 필요한지 알겠다" → "설치가 됐는지 내가 확인할 수 있다" → "막혀도 어디를 봐야 할지 안다."

## 1. 시리즈 구성

수업 시간표 순서대로 배열한다. `/tools` 목록과 각 글의 "다음 글" 링크도 이 순서를 따른다.

| 순서 | slug | 도구 | 한 줄 정의 | 수업 시점 | 선행 설치(글 앞 링크) |
|---|---|---|---|---|---|
| 1 | `tools-nodejs` | Node.js | 내 컴퓨터에서 자바스크립트 프로그램을 실행하는 엔진 | 00:20 설치 | 없음 |
| 2 | `tools-ffmpeg` | FFmpeg | 영상·음성 파일을 자르고 붙이고 변환하는 도구 | 00:20 설치 | 없음 |
| 3 | `tools-git` | Git | 파일 변경 이력을 저장하고 공개된 프로그램을 내려받는 도구 | 00:20 설치 | 없음 |
| 4 | `tools-hyperframes` | Hyperframes | HTML로 만든 장면을 시간 흐름에 맞춰 MP4 영상으로 만드는 도구 | 00:20 설치, 01:10·02:10 실습 | Node.js, FFmpeg |
| 5 | `tools-aside` | Aside 브라우저 | 사람과 AI가 함께 쓰는 브라우저, aside-cli로 AI가 브라우저를 다룸 | 00:40 설정 | 없음(aside-cli는 3장 확인 사항) |
| 6 | `tools-python` | Python | Whisper 같은 AI 프로그램을 실행하는 언어·실행 환경 | 01:40 이전 | 없음 |
| 7 | `tools-whisper` | Whisper | 음성을 글과 시간표(자막)로 바꾸는 도구 | 01:40 설치, 01:50 전사 | Python, FFmpeg |
| 8 | `tools-concat` | Concat | 내 컴퓨터에서 돌아가는 무료 오픈소스 영상 편집기 | 02:40 설치, 03:00 편집 | 없음(설치 파일 기준) |
| 9 | `tools-kie-ai` | kie.ai | 여러 영상·이미지 생성 AI를 API 하나로 쓰게 해 주는 서비스 | 03:20 광고 영상 | 없음(계정·API 키·크레딧 필요) |

선행 관계 요약

```
Node.js ─┐
         ├─▶ Hyperframes
FFmpeg ──┤
         ├─▶ Whisper
Python ──┘
Git ─────▶ (Concat 소스 빌드 등, 선택)
```

## 2. 글 한 편의 틀

블로그 본문은 `text`·`image`·`prompt` 블록을 쓰며, 텍스트 안에서는 `## 소제목`, `> 인용`, 코드 블록, `![설명](이미지)`만 지원한다. 목록·표·작은 소제목은 렌더링되지 않으므로 아래 틀은 이 범위 안에서 쓴다.

| 순서 | 블록 | 내용 | 블로그에서 쓰는 형식 |
|---|---|---|---|
| 0 | 먼저 설치하세요 | 선행 도구 글 링크. 없으면 "준비물 없이 바로 시작합니다" | 본문 맨 앞 `> 인용` 한 개 |
| 1 | 한 줄 정의 | 전문 용어 없이 "무엇을 하는 도구인가" | 첫 문단 |
| 2 | 생활 속 비유 | 예: FFmpeg = 영상 파일 전용 만능 가위·풀 | 문단 |
| 3 | 이 수업에서 하는 일 | 수업의 어느 단계에서 왜 필요한지 | `## 이 수업에서 하는 일` |
| 4 | 윈도우에 설치하기 | 공식 배포처와 단계 | `## 설치하기`, 단계는 문단 안 `1) 2) 3)` 줄바꿈 + 화면 캡처 이미지 |
| 5 | 설치 확인 | 확인 명령과 정상 출력 예시 | 코드 블록 2개(명령, 출력) |
| 6 | 처음 써 보기 | 따라 할 수 있는 예제 2~3개 | 코드 블록 + 설명 문단. AI에게 하는 요청 예시는 `prompt` 블록 |
| 7 | 자주 막히는 곳 | 오류 메시지 → 뜻 → 해결 | `## 자주 막히는 곳`, 오류 문구는 코드 블록 |
| 8 | 용어 풀이 | 낯선 단어 3~6개 | 문단, "용어: 설명" 줄바꿈 |
| 9 | 맥에서는 | 맥 설치 명령 차이만 짧게 | `## 맥에서는` |
| 10 | 다음 글 / 더 알아보기 | 시리즈 다음 글, 공식 문서, 확인일 | 마지막 문단 |

### 선행 도구 링크 쓰는 법

본문 맨 앞을 다음처럼 쓴다.

```
> 먼저 설치하세요: https://www.letscoding.kr/blog/tools-nodejs https://www.letscoding.kr/blog/tools-ffmpeg
```

본문 렌더러가 우리 블로그 주소를 **공개된 글의 제목 링크**로 바꿔 준다. 대상 글이 아직 공개 전이면 주소가 그대로 노출되므로, **선행 도구 글을 먼저 공개**한다(5장 순서).

### 공통 원칙

- 명령어는 PowerShell 기준. 각 명령 바로 아래 "이 명령이 하는 일"을 한 문장으로 붙인다.
- 설치는 공식 배포처 또는 `winget`만 안내한다. 버전·명령은 바뀌므로 글 끝에 확인일을 적는다.
- 회사 PC 제약(설치 권한, 사내망 차단, 백신 경고)을 "자주 막히는 곳"에 넣는다. 수업 계획서의 사전 확인 항목과 문구를 맞춘다.
- 녹음·화면 자료에 고객 정보·API 키가 보이지 않게 하라는 수업 계획서의 주의를 Whisper·Hyperframes·kie.ai 글에 넣는다.
- 설치 후 "터미널(PowerShell)을 새로 열어야 명령을 찾는다"는 안내는 모든 설치 글에 반복한다. 윈도우 입문자가 가장 많이 막히는 지점이다.

## 3. 도구별 내용 계획

### 3-1. Node.js — `tools-nodejs`

- **비유:** 앱을 돌리는 엔진. Hyperframes라는 자동차가 움직이려면 이 엔진이 필요하다.
- **수업에서:** Hyperframes를 `npx`로 실행할 때 쓴다. 코드를 직접 쓰지 않아도 설치는 필요하다.
- **설치:** nodejs.org LTS 설치 파일(.msi) 또는 `winget install OpenJS.NodeJS.LTS`.
- **확인:** `node -v`가 `v22` 이상, `npm -v`.
- **써 보기:** `node -e "console.log('안녕하세요')"`, `npx --version`.
- **막히는 곳:** `'node'은(는) 내부 또는 외부 명령...이 아닙니다`(새 창 열기), PowerShell 실행 정책 때문에 `npx` 스크립트 차단, 버전이 22 미만, 사내 프록시로 다운로드 실패.
- **용어:** 자바스크립트, 런타임, npm, npx, LTS.

### 3-2. FFmpeg — `tools-ffmpeg`

- **비유:** 영상 파일 전용 만능 가위와 풀, 포장기.
- **수업에서:** Hyperframes가 장면을 MP4로 만들 때, Whisper가 음성을 읽을 때 뒤에서 일한다.
- **설치:** `winget install Gyan.FFmpeg`를 기본으로. 수동 설치(압축 해제 + PATH 등록)는 막혔을 때의 대안으로 화면 캡처와 함께.
- **확인:** `ffmpeg -version`.
- **써 보기:** `ffprobe`로 파일 정보 보기, 10초 자르기, MP4에서 음성만 MP3로 뽑기.
- **막히는 곳:** PATH 미등록, 파일 경로의 공백·한글(따옴표로 감싸기), 결과 파일이 재생되지 않음(코덱).
- **용어:** 코덱, 인코딩, 컨테이너(MP4·MOV), 프레임레이트, 비트레이트.

### 3-3. Git — `tools-git`

- **비유:** 문서의 "버전 기록", 저장할 때마다 찍어 두는 사진첩.
- **수업에서:** GitHub에 공개된 프로그램과 예제를 내려받는다(`git clone`). 영상 프로젝트를 고치다 되돌리는 법은 선택 내용.
- **설치:** git-scm.com의 Git for Windows 또는 `winget install Git.Git`. 설치 마법사 선택지는 기본값 유지를 권장하고 주요 화면만 캡처.
- **확인:** `git --version`.
- **써 보기:** `git clone` → `cd`로 폴더 이동 → `git log`.
- **막히는 곳:** 사내망의 GitHub 차단, 같은 이름의 폴더가 이미 있음, 긴 경로 오류.
- **용어:** 저장소(repository), clone, commit, GitHub.
- branch·merge 같은 협업 개념은 다루지 않는다고 명시한다.

### 3-4. Hyperframes — `tools-hyperframes`

- **선행:** Node.js(22 이상), FFmpeg.
- **정의:** HTML·CSS로 만든 화면과 이미지·음성을 시간 흐름에 맞춰 배치하고 MP4로 렌더링하는 오픈소스 도구(HeyGen 공개, Apache 2.0).
- **비유:** 웹페이지로 만드는 파워포인트 애니메이션. 장면을 웹페이지처럼 만들면 Hyperframes가 한 프레임씩 촬영해 영상으로 묶는다.
- **수업에서:** 01:10 모션그래픽 예제, 02:10 준비된 화면 자료로 설명 영상 제작. AI(Codex)에 Hyperframes 스킬로 장면을 요청하고, 사람은 미리보기로 확인하며 수정을 요청한다.
- **써 보기:** `npx hyperframes init 프로젝트이름` → `npx hyperframes preview` → `npx hyperframes render`. AI에게 보내는 요청 예시는 `prompt` 블록으로.
- **막히는 곳:** Node 버전 부족, FFmpeg 미설치, 렌더링이 느림(정상 범위 안내), 한글 글꼴 깨짐, 미리보기용 브라우저 다운로드 차단.
- **용어:** HTML, CSS, 컴포지션, 렌더링, 프레임, 스킬(AI에 주는 작업 설명서).
- 한국어 자료가 거의 없으므로 시리즈에서 가장 공들여 쓴다. 정확한 명령·옵션은 작성 시 공식 저장소로 다시 확인한다.

### 3-5. Aside 브라우저 — `tools-aside`

- **정의:** 사람과 AI 에이전트가 함께 쓰는 브라우저. 로그인한 웹사이트에서 AI가 대신 작업할 수 있고, 메모리는 내 기기에 저장된다.
- **비유:** 옆자리 동료가 내 화면을 같이 보며 대신 클릭해 주는 브라우저.
- **수업에서:** 00:40 설치·로그인, aside-cli로 AI(Codex)가 브라우저를 다룰 수 있게 연결한다.
- **설치:** aside.com/download의 윈도우 설치 파일.
- **aside-cli:** 공개 자료에서 확인한 설치 명령은 맥·리눅스용 스크립트뿐이다. 윈도우 설치 방법은 작성 전 공식 문서나 강사 환경에서 확인한다(6장).
- **막히는 곳:** 회사 PC의 브라우저 설치 제한, 로그인 계정, 기존 브라우저 북마크 가져오기.
- **보안 문단:** AI가 로그인된 사이트에서 일할 수 있으므로, 실습에서는 업무 계정 대신 실습용 계정을 쓰도록 권한다.

### 3-6. Python — `tools-python`

- **정의:** 많은 AI 도구가 만들어진 프로그래밍 언어이자, 그 프로그램을 실행하는 환경.
- **수업에서:** Whisper를 설치하고 실행하는 데 필요하다. 코드를 직접 쓰지는 않는다.
- **설치:** python.org의 **Python 3.11** 윈도우 설치 파일. 공식 Whisper가 시험한 범위가 3.8~3.11이라 3.11로 맞춘다. 설치 첫 화면의 **"Add python.exe to PATH" 체크**를 캡처로 강조한다.
- **확인:** `py --version`, `py -3.11 -m pip --version`.
- **막히는 곳:** `python`을 입력하면 Microsoft Store가 열림(앱 실행 별칭), PATH 체크 누락, 여러 버전이 섞임(`py -3.11`로 지정).
- **용어:** 인터프리터, pip, 패키지, 가상환경(이 수업에서는 쓰지 않는다고 명시).

### 3-7. Whisper — `tools-whisper`

- **선행:** Python 3.11, FFmpeg.
- **정의:** OpenAI가 공개한 음성 인식 모델. 녹음을 넣으면 글과 "몇 초에 무슨 말을 했는지" 시간표를 만든다.
- **비유:** 받아쓰기를 아주 잘하는 속기사.
- **수업에서:** 01:50 설명 녹음을 전사하고 타임테이블을 정리한다. 이 시간표가 Hyperframes 장면 전환과 자막의 기준이 된다.
- **설치:** `py -3.11 -m pip install -U openai-whisper`. PyTorch 등 큰 파일을 함께 내려받으므로 시간이 걸린다고 안내한다.
- **확인:** `whisper --help`(안 되면 `py -3.11 -m whisper --help`).
- **써 보기:** `whisper 녹음.mp3 --language Korean --model small` → `.txt`·`.srt` 결과 비교.
- **모델 선택:** 일반 노트북(그래픽카드 없음)에서는 처리가 느리므로 수업은 `small`을 기준으로 하고, `turbo`·`medium`은 정확도와 시간의 교환으로 소개한다. 첫 실행 때 모델 파일을 내려받는다.
- **막히는 곳:** FFmpeg를 못 찾음, 모델 다운로드 차단(사내망), 첫 실행이 느림, 제품명·고유명사 오인식(결과 검토가 필요한 이유와 연결), `whisper` 명령을 못 찾음(Scripts 폴더 PATH).
- **용어:** 전사, 모델, 타임코드, SRT 자막, PyTorch.
- 녹음은 내 컴퓨터에서 처리된다는 점과, 그래도 고객 정보가 담긴 녹음은 쓰지 말라는 점을 함께 적는다.

### 3-8. Concat — `tools-concat`

- **정의:** 계정·워터마크 없이 내 컴퓨터에서 돌아가는 무료 오픈소스 영상 편집기. AI가 편집을 조작할 수 있는 연결 통로(MCP 서버, API)를 갖고 있다.
- **비유:** 캡컷 같은 편집기인데, AI에게 "이 구간을 앞으로, 이 부분은 1.5배속" 하고 맡길 수 있는 편집기.
- **수업에서:** 02:40 설치·실행, 03:00 Computer Use로 하이라이트 순서와 영상 속도를 편집한다.
- **설치:** GitHub 릴리스의 윈도우 설치 파일(`Concat-<버전>-windows-x86_64-setup.exe` 또는 `.msi`). 확인 시점 최신은 v0.2.8(2026-10-20). 업데이트가 잦으므로 "가장 위의 Latest를 받으세요"로 쓴다.
- **소스로 빌드하기(선택, 짧게):** `git clone` 후 직접 빌드하려면 Rust, cmake, C++ 컴파일러, FFmpeg 개발 파일이 필요하다. 입문자에게는 설치 파일을 권한다고 밝히고 Git 글을 링크한다.
- **막히는 곳:** Windows SmartScreen 경고("추가 정보 → 실행"), 회사 PC 설치 차단.
- **용어:** 오픈소스, 릴리스, 타임라인, MCP.

### 3-9. kie.ai — `tools-kie-ai`

- **정의:** 여러 회사의 영상·이미지 생성 AI를 API 하나로 쓰게 해 주는 서비스.
- **비유:** 여러 AI 스튜디오를 한 창구에서 예약하는 대행사.
- **수업에서:** 03:20 광고 영상 장면을 생성하고, 만든 장면을 기존 영상에 붙인다.
- **준비:** 회원가입, API 키 발급, 크레딧 충전. 계정 제공·비용 부담은 교육 담당자 안내를 따른다는 수업 계획서 문구를 그대로 옮긴다.
- **써 보기:** AI(Codex)에게 API 키를 환경변수로 넘기고 장면 생성을 요청하는 `prompt` 예시. 생성은 몇 분 걸리는 비동기 작업이라 "요청 → 기다림 → 결과 받기" 흐름을 그림으로.
- **보안 문단:** API 키는 비밀번호와 같다. 화면 캡처·녹화·채팅에 노출하지 않고, 노출되면 즉시 재발급한다.
- **막히는 곳:** 크레딧 부족, 생성 대기 지연(수업에서는 강사 예제로 이어감), 결과 링크 만료(받으면 바로 내려받기).
- **용어:** API, API 키, 크레딧, 비동기 작업, 환경변수.
- 가격·모델 목록·저장 기간은 자주 바뀌므로 숫자를 본문에 박지 않고 공식 가격 페이지로 링크한다.

## 4. 구현

### 4-1. 블로그 글

- 관리자 편집기(`/blog/editor`)로 작성한다. 갈래는 `info`.
- 제목은 검색어를 앞에 둔다. 예: "FFmpeg 윈도우 설치 방법과 처음 쓰는 명령 3가지", "Whisper 한국어 음성 전사, 윈도우에서 설치부터 자막까지".
- 대표 이미지는 시리즈 공통 디자인(도구 이름 + 아이콘)으로 통일한다.
- 설치 화면 캡처는 이미지 블록으로 넣는다. 편집기는 이미지 파일 업로드를 아직 지원하지 않으므로 Supabase Storage에 올린 뒤 URL을 넣는다.

### 4-2. `/tools` 허브 페이지

- 저장소 안 정적 페이지(`src/app/tools/page.tsx`). 시리즈 slug 순서를 코드에 두고 `getPosts()`로 공개된 글의 제목·요약을 가져온다. 아직 공개 전인 글은 `준비 중`으로 표시한다. DB 변경은 필요 없다.
- 상단: 도구들이 이어지는 흐름도(HTML/SVG). 음성 → Whisper → 시간표 → Hyperframes(Node.js가 실행, FFmpeg가 MP4로) → 완성 영상 → Concat 편집 · kie.ai 생성 장면 추가.
- 중단: 수업 순서대로 9개 글 카드(도구 이름, 한 줄 정의, 선행 도구 표시, 글 링크).
- 하단: 수업 전 설치 체크리스트 — 확인 명령 한 줄씩(`node -v`, `ffmpeg -version`, `git --version`, `py --version`, `whisper --help` 등).
- 터미널을 처음 여는 사람을 위한 짧은 안내(PowerShell 여는 법)를 허브에 둔다. 모든 글이 이 안내를 링크한다.
- `ItemList` 구조화 데이터, 사이트맵 등록, 메타 설명.

### 4-3. 블로그 기능 보강(선택)

글을 쓰기 전에 하면 좋은 것. 없어도 시리즈는 쓸 수 있다.

- 코드 블록 복사 버튼: 명령어를 따라 치는 글이라 효과가 크다.
- 텍스트 블록의 `- 목록`·`1. 번호 목록` 지원: 온보딩 가이드에는 이미 있으므로 같은 파서를 블로그에도 쓰면 설치 단계가 읽기 쉬워진다.
- 글 상세 하단의 "시리즈 다음 글" 자동 링크(`/tools`의 순서 재사용).

## 5. 작업 순서

1. (선택) 4-3 블로그 기능 보강
2. `/tools` 허브 페이지 — 모든 글이 `준비 중`인 상태로 먼저 배포해도 된다
3. 선행 도구 글을 먼저 공개: Node.js → FFmpeg → Python → Git
4. Hyperframes, Whisper(선행 글 링크가 제목으로 보이는지 확인)
5. Aside, Concat, kie.ai
6. 윈도우 실제 PC(관리자 권한 없는 계정 포함)에서 글만 보고 처음부터 따라 해 보며 검수. 정상 출력 예시는 실제 출력으로 교체
7. 수업 계획서의 "수업 자료와 설치 안내"에 `/tools` 링크 추가

## 6. 작성 전 확인할 것

- **aside-cli 윈도우 설치 방법:** 공개 자료에는 맥·리눅스용 설치 스크립트만 있다. 윈도우 지원 여부와 명령을 공식 문서나 강사 환경에서 확인한다.
- **Hyperframes 윈도우 동작:** `init/preview/render`가 윈도우 PowerShell에서 그대로 되는지, 렌더링용 브라우저를 따로 받는지 실제 PC에서 확인한다.
- **Whisper 설치 용량·시간:** 윈도우에서 `pip install openai-whisper`가 내려받는 크기와 시간을 재서 글과 사전 안내에 적는다. 수업 중 설치(01:40, 10분)에 맞는지도 판단한다.
- **Python 3.12 이상:** 공식 Whisper가 시험한 범위는 3.11까지다. 더 높은 버전에서도 되는지 확인되기 전까지는 3.11로 안내한다.
- **Concat 실행에 FFmpeg가 따로 필요한지:** 설치 파일에 포함되어 있는지 확인한다. 필요하면 FFmpeg 글을 선행 링크로 넣는다.
