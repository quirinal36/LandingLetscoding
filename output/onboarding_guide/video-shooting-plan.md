# 가이드 영상 촬영 계획

[재촬영 구성안](video-reshoot-plan.md)의 A·B·C 시리즈를 가이드 페이지(`/guide`)의 세션 > 편 > 소제목 구조로 옮기고, 편마다 화면 기준 대본과 준비물을 적은 문서입니다. 같은 내용이 `landing.guide_lessons`(목차·교재 본문)와 `landing.guide_lesson_notes`(촬영 메모)에 초기 데이터로 들어가며, 이후 수정은 `/guide/editor`에서 합니다. 이 문서는 초안 기록이고 최신 상태는 가이드 페이지가 기준입니다.

## 영상 등록 흐름

1. 아래 대본대로 촬영하고 편집합니다. 소제목 목록이 곧 유튜브 챕터 초안입니다.
2. 유튜브에 올린 뒤 카카오 로그인으로 `/guide/editor?slug=편주소`를 열어 유튜브 주소를 붙여 넣습니다.
3. 소제목마다 시작 시간(mm:ss)을 적으면 가이드 페이지에서 챕터를 누를 때 그 지점부터 재생됩니다.
4. 교재 본문을 영상 내용에 맞게 다듬고 `완성` 체크를 켭니다. 체크 전까지는 목차에 `준비 중`으로 표시됩니다.

## 촬영 전 공통 준비

- [ ] 시연용 기관·클래스·학생 계정을 가명으로 준비하고 데이터를 미리 채운다. 작품 등록 한도를 해제한다.
- [ ] AI 생성 결과물은 미리 만들어 두고, 대기 화면은 편집으로 잘라낸다.
- [ ] 썸네일 임시 파일 정리, 화면 반영 지연 같은 알려진 문제는 해결하거나 편집으로 정리한다.
- [ ] 대본은 '어디를 누르면 무엇이 바뀌는지' 단위로 쓴다. 시연 중 정정이 나오지 않게 한다.
- [ ] 브라우저 배율 125~150%, 마우스 강조 효과.
- [ ] 자막과 유튜브 챕터 타임스탬프를 기본으로 넣는다.
- [ ] 요금, '테스트 중' 같은 시점 의존 표현은 본편에서 뺀다.

## 촬영 우선순위

1. 1.1 렛츠코딩 라운지 한눈에 보기 (소개 영상)
2. 3.1~3.3 학생 과제 한 바퀴, 4.1 과제 검토와 완료 처리
3. 2.1~2.3 기관과 클래스 설정
4. 나머지 편과 6.1 구구단 스네이크 시연. 7부 부록은 영상 없이 글로 운영한다.

1·2번에 기존 영상에서 전달하려던 내용 대부분이 들어갑니다. 소개 영상의 '수업 한 사이클' 구간은 2번에서 녹화한 장면을 재사용하므로, 실제 촬영은 2번을 먼저 해도 됩니다.

## 편별 계획

### 1부. 시작하기 전에

렛츠코딩 라운지가 어떤 수업을 위한 도구인지, 어떤 흐름으로 쓰는지 전체 그림을 먼저 봅니다. 도입을 검토하는 원장과 처음 접하는 교사가 보는 자리입니다.

#### 1.1 렛츠코딩 라운지 한눈에 보기

- **화면:** 전체
- **목표 길이:** 10분
- **가이드 주소:** `/guide/overview`
- **요약:** 학생이 만든 구구단 스네이크에서 시작해, 아이디어가 작품이 되고 교사가 검토하는 수업 한 사이클을 10분 안에 봅니다.

소제목(유튜브 챕터 초안):

1. 완성작부터 보기
2. 왜 이 도구를 만들었나
3. 수업 한 사이클
4. 교사가 볼 수 있는 것
5. 활동을 이어가게 하는 장치
6. 다음 단계

촬영 메모:

> 목표 8~12분. 대상: 도입을 검토하는 원장. 기존 영상 1·2·10장을 압축한다.
>
> [화면 기준 대본]
> 1. (0:00) 구구단 스네이크 플레이 화면 20초 → 학생 소개 쇼츠 20초. 자막: '학생이 규칙을 정하고 AI에게 요청해 만든 게임'.
> 2. (1:00) 외부 도구 로그인·구독 화면을 짧게 보여 주며 문제 세 가지를 자막 카드로. 실제 계정 정보는 가린다.
> 3. (2:30) 수업 한 사이클: 단계마다 30초 이내. 과제 시작 → 스튜디오 요청 → 실행·수정 → 개발일지 → 게시 → 교사 완료 처리. 각 장면은 따라 하기 편에서 녹화한 것을 재사용한다.
> 4. (7:00) 교사 화면: 학생 AI 대화 기록 → 과제 현황 → 클래스 AI 설정. 원장에게 가장 설득력 있는 구간이므로 천천히.
> 5. (9:00) 투자·배지 화면과 건의함의 실제 의견 1~2개(학생 이름 가림).
> 6. (10:00) 다음 단계 안내 카드: 가이드 페이지 주소.
>
> [준비물] 시연용 기관·클래스·학생 계정(가명), 완성된 구구단 스네이크 작품, 건의함 캡처, 쇼츠 원본.
> [주의] 요금·'테스트 중' 표현은 넣지 않는다. 생성 대기 화면은 편집으로 잘라낸다.

#### 1.2 안심하고 쓸 수 있는 이유

- **화면:** 전체
- **목표 길이:** 3분
- **가이드 주소:** `/guide/safety`
- **요약:** 실명을 쓰지 않는 공개 활동명, 교사가 확인하는 AI 대화, 클래스 단위 AI 제한. 학부모 상담에 그대로 쓸 수 있는 세 가지입니다.

소제목(유튜브 챕터 초안):

1. 공개 활동명에는 실명을 쓰지 않습니다
2. 교사가 학생의 AI 대화를 확인합니다
3. 클래스 단위로 AI 수준과 모드를 제한합니다
4. 학부모 상담에 쓰기

촬영 메모:

> 목표 3분. 소개 영상 앞부분에도 같은 내용을 1분으로 압축해 넣는다. 기존 13장에서 잠깐 언급한 내용을 독립시킨 편.
>
> [화면 기준 대본]
> 1. 학생 프로필 공개 화면: 활동명만 보이는 모습 → 관리자 화면에서 실명이 보이는 모습 비교.
> 2. 스튜디오 교사 화면에서 학생 AI 대화 기록을 여는 장면.
> 3. 클래스 설정 화면에서 AI 수준·모드를 바꾸는 장면. '클래스 단위'라는 자막 고정.
> 4. 마무리 자막 카드: 상담용 한 문장.
>
> [준비물] 가명 학생 계정 2개(다른 클래스), 미리 남겨 둔 AI 대화 기록.

### 2부. 기관과 클래스 설정

관리자 화면에서 합니다. 기관을 개설하고 교사와 클래스를 만들고 학생을 등록하면 과제를 시작할 준비가 끝납니다. 이 순서대로 해야 다음 세션을 따라 할 수 있습니다.

#### 2.1 기관 개설 신청과 기본 설정

- **화면:** 관리자
- **목표 길이:** 5분
- **가이드 주소:** `/guide/organization`
- **요약:** 회원가입과 별개로 기관을 개설하고 승인을 받습니다. 기관 정보와 전용 주소, 브랜드 색상을 정하는 첫 단계입니다.

소제목(유튜브 챕터 초안):

1. 회원가입과 기관 개설은 별개입니다
2. 기관 개설 신청서 작성
3. 승인 대기와 승인 후
4. 기관 정보와 브랜드 다듬기

촬영 메모:

> 목표 5분. 기존 영상 13장 전반부.
>
> [화면 기준 대본]
> 1. 회원가입 화면 → 이메일 인증 메일 → 계정 정보 입력. 인증 대기는 편집으로 자른다.
> 2. 기관 개설 신청 화면: 항목을 위에서 아래로 한 번에 채운다. 담당자 정보는 시연용 값.
> 3. 신청 완료 → 대기 상태 화면 → (편집 점프) 승인된 상태 화면. 승인은 플랫폼 관리자 계정으로 미리 처리해 둔 기관을 보여 준다.
> 4. 플랜 부여 화면 → 관리 도구 첫 화면.
> 5. 기관 정보 수정 화면에서 브랜드 색을 바꿔 전용 주소 화면이 바뀌는 것을 확인.
>
> [준비물] 승인 전·후 두 상태의 시연 기관, 시연용 이메일 계정.
> [주의] 구독·요금 화면은 이 편에 넣지 않는다.

#### 2.2 교사 권한과 클래스 만들기

- **화면:** 관리자
- **목표 길이:** 6분
- **가이드 주소:** `/guide/classes`
- **요약:** 교사를 초대해 담당 클래스를 정하고, 클래스마다 사용할 AI 수준과 모드를 설정합니다.

소제목(유튜브 챕터 초안):

1. 원장 계정의 두 역할
2. 교사 초대와 담당 클래스
3. 클래스 만들기
4. 클래스별 AI 수준과 모드

촬영 메모:

> 목표 6분. 기존 13장 후반과 14장의 클래스 설정.
>
> [화면 기준 대본]
> 1. 관리자 화면과 교사 화면을 전환해 보여 주며 '같은 계정, 두 역할' 자막.
> 2. 교사 추가 → 담당 클래스 지정. 시연 교사 계정은 가명.
> 3. 클래스 만들기: 이름 입력 → 담당 교사 선택 → 저장. 두 개 만든다(저학년 반, 고학년 반).
> 4. 클래스 AI 설정: 두 반을 다르게 설정하고 학생 화면에서 선택지가 달라지는 것을 바로 확인한다.
>
> [주의] 기존 영상에서 '학생 단위'라고 말한 뒤 정정한 부분. 대본에 '클래스 단위'를 처음부터 명시한다.

#### 2.3 학생 등록

- **화면:** 관리자
- **목표 길이:** 5분
- **가이드 주소:** `/guide/students`
- **요약:** 학생이 기관 코드로 가입하거나, 이미 가입한 학생을 이메일로 찾아 기관에 추가합니다. 공개 활동명 원칙도 함께 안내합니다.

소제목(유튜브 챕터 초안):

1. 두 가지 등록 방법
2. 기관 코드로 가입하기
3. 이미 가입한 학생 추가하기
4. 공개 활동명과 등록 확인

촬영 메모:

> 목표 5분. 기존 14장의 학생 소속 등록.
>
> [화면 기준 대본]
> 1. 관리자 화면에서 기관 코드 확인.
> 2. (학생 화면) 가입 중 기관 코드 입력 → 가입 완료. 활동명 입력란에서 '실명 대신 활동명' 자막.
> 3. (관리자 화면) 학생 목록에 새 학생 표시 → 클래스 배정.
> 4. 이메일 검색으로 기존 학생 추가 → 클래스 배정.
> 5. 클래스별 학생 목록 확인.
>
> [준비물] 가명 학생 계정 2개(신규 가입용 이메일 1개, 기존 가입 1개).

### 3부. 학생 과제 한 바퀴

학생 화면에서 과제 하나가 시작부터 게시까지 어떻게 진행되는지 봅니다. 구구단 스네이크를 예로 들어 세 편으로 나눴습니다.

#### 3.1 과제 시작과 아이디어 기록

- **화면:** 학생
- **목표 길이:** 5분
- **가이드 주소:** `/guide/start-assignment`
- **요약:** 추천 과제를 시작하고, 만들고 싶은 게임의 규칙을 과제 대화창에 기록합니다. 학생 수준에 따라 구상의 깊이를 조절하는 방법도 다룹니다.

소제목(유튜브 챕터 초안):

1. 추천 과제 시작하기
2. 아이디어 기록하기
3. 학생 수준에 맞게 구상하기
4. 첫 수업은 익숙한 게임에서

촬영 메모:

> 목표 5분. 기존 1·2장.
>
> [화면 기준 대본]
> 1. 학생 로그인 → 추천 과제 목록 → 과제 시작 → 내 과제 페이지.
> 2. 과제 대화창에 아이디어 입력. 타이핑은 편집으로 빠르게.
> 3. 저학년 학생 기록(한 문장)과 고학년 학생 기록(순서도 사진) 화면 분할 비교.
> 4. 마무리 자막: '먼저 재현, 그다음 나만의 규칙'.
>
> [준비물] 가명 학생 계정 2개에 미리 남긴 아이디어 기록, 순서도 사진.

#### 3.2 스튜디오에서 만들고 고치기

- **화면:** 학생
- **목표 길이:** 8분
- **가이드 주소:** `/guide/studio-build`
- **요약:** 스튜디오에서 프로젝트를 만들고 AI에게 요청합니다. 의도와 다르게 나온 결과를 실행해 보며 찾아내고 수정하는 과정이 이 편의 중심입니다.

소제목(유튜브 챕터 초안):

1. 새 프로젝트 만들기
2. 모델 고르기
3. 기본 게임 요청하기
4. 의도와 다른 결과 찾기
5. 웹 작품의 구조 알기

촬영 메모:

> 목표 8분. 기존 3·6장을 합치되 스튜디오를 기본 방법으로 한다. 외부 도구 제작은 보여 주지 않는다.
>
> [화면 기준 대본]
> 1. 스튜디오 진입 → 새 프로젝트 → 파일 목록(HTML/CSS/JS/기획 문서) 설명 20초.
> 2. 모델 선택. 클래스 설정으로 제한된 선택지가 보이는 상태.
> 3. 기본 스네이크 요청 → (편집 점프) 완성 → 규칙 추가 요청 → (편집 점프) 완성.
> 4. 실행: 숫자가 작게 보이는 결과(미리 만들어 둔 버전) → 학생이 알아차리는 장면 → 수정 요청 → 바뀐 화면. 이 구간에 2분 이상 쓴다.
> 5. HTML/CSS/JS 역할 자막 카드 15초.
>
> [준비물] '숫자가 작은 버전'과 '수정된 버전' 두 프로젝트를 미리 만들어 둔다. 생성 대기 화면은 전부 잘라낸다.
> [주의] '테스트 단계' 같은 표현 금지.

#### 3.3 제작 지원 기능, 개발일지, 라운지 게시

- **화면:** 학생
- **목표 길이:** 7분
- **가이드 주소:** `/guide/devlog-publish`
- **요약:** 준비된 요청문으로 랭킹을 넣고, 썸네일을 만들고, 개발일지를 쓴 뒤 라운지에 게시합니다. 과제 진행 단계가 어떻게 채워지는지도 봅니다.

소제목(유튜브 챕터 초안):

1. 준비된 요청문 쓰기
2. 썸네일 만들기
3. 개발일지 쓰기
4. 라운지에 게시하기
5. 과제 진행 단계 확인

촬영 메모:

> 목표 7분. 기존 4·7장.
>
> [화면 기준 대본]
> 1. 준비된 요청문 목록 → 랭킹 추가 요청 → (편집 점프) 랭킹이 보이는 실행 화면.
> 2. 이미지 생성 모드 → 썸네일 생성 → 대표 이미지 적용. 임시 파일 정리와 반영 지연 문제는 해결 뒤 촬영하거나 편집으로 정리.
> 3. 개발일지 초안 요청 → 초안 → 학생이 한 줄 고치는 장면 → 등록.
> 4. 게시 화면: 필수 정보 입력 → 게시 완료. 시연 계정의 월간 등록 한도를 미리 해제해 둔다.
> 5. 과제 페이지에서 단계가 채워진 모습.
>
> [주의] 기존 영상의 '등록 한도 도달로 게시 실패'가 재발하지 않도록 촬영 전 반드시 확인.

### 4부. 교사의 검토와 지도

교사 화면에서 학생이 제출한 과제를 검토하고, 완성작에 질문을 던지고, 학생이 스스로 과제를 만들도록 이끄는 방법입니다.

#### 4.1 과제 검토와 완료 처리

- **화면:** 교사
- **목표 길이:** 5분
- **가이드 주소:** `/guide/review`
- **요약:** 미확인 과제와 학생의 대화를 확인하고 완료·반려·되돌리기를 처리합니다. 완료된 과제에는 보상이 지급됩니다.

소제목(유튜브 챕터 초안):

1. 미확인 과제 확인하기
2. 완료, 반려, 되돌리기
3. 무엇을 기준으로 완료할까

촬영 메모:

> 목표 5분. 기존 9장 전반.
>
> [화면 기준 대본]
> 1. 교사 화면 → 과제 관리 → 미확인 과제 목록.
> 2. 과제 하나 열기: 대화 기록 → 개발일지 → 게시 작품 순으로 스크롤.
> 3. 완료 처리 → 보상 지급 표시. 다른 과제는 반려(이유 입력). 완료한 과제를 진행 중으로 되돌리는 장면.
> 4. 완료 기준 자막 카드.
>
> [준비물] 제출 상태의 가명 학생 과제 3개(완료용·반려용·되돌리기용).

#### 4.2 학생이 직접 만드는 자율 과제

- **화면:** 학생·교사
- **목표 길이:** 4분
- **가이드 주소:** `/guide/self-assignment`
- **요약:** 추천 과제를 벗어나 학생이 생활 속 불편에서 찾은 문제를 과제로 등록합니다. 급식 줄 대기 시간 앱이 예입니다.

소제목(유튜브 챕터 초안):

1. 추천 과제에서 자율 과제로
2. 생활 속 문제에서 과제 만들기
3. 교사의 역할

촬영 메모:

> 목표 4분. 기존 9장 후반.
>
> [화면 기준 대본]
> 1. (학생) 과제 만들기 → 제목·설명 입력('급식 줄 대기 시간 앱') → 등록.
> 2. (교사) 과제 관리에서 새 자율 과제 확인 → 대화창에 범위 조정 조언 한 줄 남기기.
> 3. 자막 카드: '큰 아이디어는 첫 기능 하나로'.
>
> [준비물] 가명 학생 계정, 미리 작성한 조언 문장.

#### 4.3 완성작에 던지는 교사의 질문

- **화면:** 교사
- **목표 길이:** 영상 없음(글 자료)
- **가이드 주소:** `/guide/questions`
- **요약:** 작동하는 결과물이 나온 뒤에도 학생이 오류와 확장 가능성을 생각하게 하는 질문 모음입니다. 캡처해서 수업에 바로 쓸 수 있습니다.

소제목(유튜브 챕터 초안):

1. 질문 카드
2. 질문의 틀
3. 수준별로 묻기

촬영 메모:

> 영상 없이 글 자료로 운영한다. 소개 영상과 스튜디오 편에서 이 질문을 자막 카드로 쓴다. 카드 이미지는 1920×1080 한 장으로 만들어 이 페이지의 이미지 블록으로 넣는다.

### 5부. 작품 공유와 운영

작품을 더 널리 보이게 하고 반을 운영하는 도구입니다. 외부 작품 등록, 소개 영상, 통계와 소통, 투자와 배지를 다룹니다.

#### 5.1 외부 작품 등록

- **화면:** 학생
- **목표 길이:** 5분
- **가이드 주소:** `/guide/external-works`
- **요약:** 엔트리·스크래치·로블록스 작품은 링크로, 웹 작품은 파일 업로드로 라운지에 등록합니다. 작품 정보를 쓰는 요령도 함께 봅니다.

소제목(유튜브 챕터 초안):

1. 어떤 작품을 올릴 수 있나
2. 작품 정보 쓰기
3. 등록 한도

촬영 메모:

> 목표 5분. 기존 5장.
>
> [화면 기준 대본]
> 1. 작품 등록 화면 → 카테고리·제목·주소·설명·사용방법·공지사항 입력. 공지사항 활용 자막.
> 2. 기기·태그 선택 → 썸네일 등록.
> 3. 웹 작품 파일 업로드 → 게시 완료. 그다음 엔트리 링크 등록 → 게시 완료.
>
> [준비물] 업로드용 웹 작품 파일, 엔트리 공유 링크. 월간 등록 한도 확인.

#### 5.2 작품 소개 영상 만들기

- **화면:** 학생·교사
- **목표 길이:** 5분
- **가이드 주소:** `/guide/intro-video`
- **요약:** 화면 녹화로 플레이 장면을 찍고 캔바에서 편집해 유튜브에 올린 뒤 라운지에 연결합니다. 학생 영상과 교사 쇼츠 두 가지입니다.

소제목(유튜브 챕터 초안):

1. 화면 녹화
2. 캔바에서 편집
3. 유튜브에 올리고 라운지에 연결
4. 교사가 소개하는 쇼츠

촬영 메모:

> 목표 5분. 기존 8장.
>
> [화면 기준 대본]
> 1. 화면 녹화 도구 실행 → 플레이 30초 녹화.
> 2. 캔바: 가져오기 → 자르기 → 자막 → 내보내기. 각 단계 15초.
> 3. 유튜브 업로드(교사 계정) → 라운지 작품 페이지에서 영상 연결 → 작품 페이지에 영상이 보이는 모습.
> 4. 교사 쇼츠 예시 20초.
>
> [준비물] 캔바 로그인, 교사 유튜브 채널, 완성된 쇼츠 1개.

#### 5.3 운영 도구: 통계, 소통, 소식

- **화면:** 교사
- **목표 길이:** 6분
- **가이드 주소:** `/guide/operations`
- **요약:** 방문 통계와 과제 현황을 읽는 법, 라운지 안에서 학생과 대화하는 법, 소식 기능을 봅니다.

소제목(유튜브 챕터 초안):

1. 방문 통계 읽는 법
2. 학생과 소통하기
3. 소식, 배지 착용, 사용 팁

촬영 메모:

> 목표 6분. 기존 14장 후반.
>
> [화면 기준 대본]
> 1. 통계 화면: 방문·과제 현황. '화면 열어 둔 시간 포함' 자막.
> 2. 과제 대화창에서 학생과 주고받은 기록 → 작품 댓글.
> 3. 소식 작성 → 학생 화면에서 받은 모습. 배지 착용 화면. 사용 팁 위치.
>
> [준비물] 대화 기록이 있는 가명 학생 계정, 미리 쓴 소식 문구.

#### 5.4 투자와 배지 이해하기

- **화면:** 교사
- **목표 길이:** 4분
- **가이드 주소:** `/guide/motivation`
- **요약:** 작품에 가상 재화로 투자하고 활동에 따라 배지를 받는 구조입니다. 학생이 묻는 질문에 교사가 답할 수 있을 만큼 설명합니다.

소제목(유튜브 챕터 초안):

1. 투자
2. 배지
3. 운영에서 본 것

촬영 메모:

> 목표 4분. 기존 10장.
>
> [화면 기준 대본]
> 1. 작품 페이지 투자 화면 → 투자 → 가치 변화 표시.
> 2. 배지 목록 → 받은 배지 → 공지사항 배경 변화.
> 3. 건의함 의견 캡처(이름 가림).
>
> [주의] 가상 재화라는 점을 자막으로 명시.

### 6부. 클론코딩 수업 시연

라운지 작품을 그대로 따라 만들며 수업 흐름을 몸에 익히는 시연입니다. 작품은 추가되는 순서대로 쌓이며 정해진 순서가 없습니다. 어느 것부터 시작해도 됩니다.

#### 6.1 구구단 스네이크

- **화면:** 교사
- **목표 길이:** 12분
- **가이드 주소:** `/guide/snake-multiplication`
- **요약:** 익숙한 스네이크 게임에 '먹은 두 숫자의 곱이 목표 수와 같으면 성공' 규칙을 더한 작품을 처음부터 끝까지 따라 만듭니다.

소제목(유튜브 챕터 초안):

1. 원작과 규칙
2. 1단계: 기본 스네이크 재현
3. 2단계: 규칙 추가
4. 3단계: 의도와 다른 결과 고치기
5. 교사의 질문
6. 개발일지와 게시
7. 변형 아이디어

촬영 메모:

> 목표 12분. 수업 시연 형식: 교사가 학생 역할로 처음부터 끝까지 만든다.
>
> [화면 기준 대본]
> 1. 완성작 플레이 30초.
> 2. 1단계 요청 → (편집 점프) 실행.
> 3. 2단계 요청 → (편집 점프) 실행 → 차이 발견(숫자 작음) → 수정 요청 → 실행. 판정 지연도 같은 방식으로 한 번 더.
> 4. 질문 카드 자막 → 변형 하나 선택해 요청.
> 5. 개발일지 → 썸네일 → 게시 → 교사 완료 처리.
>
> [준비물] 단계별 프로젝트 3개(기본·규칙 추가·수정 완료) 미리 생성. 생성 대기는 전부 편집으로 제거.
> [유튜브 챕터] 위 7개 소제목을 그대로 챕터로 쓴다.

### 7부. 부록

영상과 따로 관리하는 자료입니다. 요금이나 조건이 바뀌면 이 페이지만 고칩니다.

#### 7.1 요금제와 사용량

- **화면:** 전체
- **목표 길이:** 영상 없음(글 자료)
- **가이드 주소:** `/guide/pricing`
- **요약:** 플랜이 어떤 역할로 나뉘는지 구조만 설명합니다. 금액과 조건은 바뀔 수 있으므로 최신 요금 안내를 따릅니다.

소제목(유튜브 챕터 초안):

1. 플랜의 역할

3. 결제와 관리자 지급

촬영 메모:

#### 7.2 자주 묻는 질문

- **화면:** 전체
- **목표 길이:** 영상 없음(글 자료)
- **가이드 주소:** `/guide/faq`
- **요약:** 설명회와 상담에서 반복해 나온 질문입니다. 질문이 늘면 소제목을 추가합니다.

소제목(유튜브 챕터 초안):

1. 파이썬 파일을 올려 실행할 수 있나요?

촬영 메모:
