# 렛츠코딩 라운지 가이드 영상 재촬영 구성안

기존 가이드 영상([video-outline.md](video-outline.md), 57분 31.5초)을 검토하고, 다시 촬영할 때의 순서와 내용을 정리한 문서입니다. 기존 영상은 수업 방법, 학생 화면, 교사 화면, 기관 관리, 요금 안내를 한 편에 담았습니다. 재촬영에서는 보는 사람과 보는 시점에 따라 영상을 나누고, 실제 사용 순서대로 배치하는 것을 기본 방향으로 삼습니다.

## 1. 기존 영상에서 고칠 점

| 문제 | 영상에서 보이는 모습 | 영향 |
| --- | --- | --- |
| 보는 사람과 목적이 섞임 | 수업 방법, 학생 화면, 교사 화면, 관리자 설정, 요금 안내가 57분짜리 한 편에 모두 들어 있음 | 도입을 검토하는 원장에게는 너무 길고, 도입 후 설정법을 찾는 교사는 필요한 구간을 찾기 어려움 |
| 실제 사용 순서와 영상 순서가 다름 | 기관 가입(13장)과 클래스 설정(14장)이 맨 끝에 나옴 | 실제로는 이 설정을 먼저 해야 학생 과제를 시작할 수 있어 따라 하기 영상으로 쓰기 어려움 |
| 한 학생의 과제가 여러 장에 흩어짐 | 과제 시작(2장), 개발일지(4장), 교사 검토(9장)가 다른 내용 사이에 나뉘어 있음 | 과제 하나가 처음부터 끝까지 어떻게 진행되는지 한눈에 보이지 않음 |
| 같은 작업을 두 번 보여 줌 | 외부 도구로 제작(3장)과 스튜디오로 제작(6장), 직접 등록(5장)과 스튜디오 게시(7장)가 겹침 | 길이가 늘어나고 어느 쪽이 기본 방법인지 헷갈림 |
| 시연 사고 | 월간 작품 등록 한도로 게시 실패, 썸네일 임시 파일 정리와 화면 반영 지연, 클래스 단위 설정을 시연 중에 정정 | 서비스가 아직 덜 만들어졌다는 인상을 줌 |
| 곧 바뀔 정보가 본편에 있음 | 요금제, 스튜디오가 초기 테스트 단계라는 안내 | 요금이나 기능이 바뀌면 영상 전체를 다시 찍어야 함 |
| 회의 대화가 남아 있음 | 11장 '직접 사용해 보며 수업 준비하기'는 원장과 나눈 대화에 가까움 | 처음 보는 사람에게는 맥락이 없음 |

## 2. 시리즈 구성

### A. 소개 영상 (도입 검토용, 8~12분)

**대상:** 렛츠코딩 라운지를 처음 알아보는 학원 원장

| 순서 | 길이 | 내용 |
| --- | --- | --- |
| 1. 완성작부터 보여 주기 | 1분 | 학생이 만든 구구단 스네이크 플레이 장면과 학생 소개 쇼츠로 시작해, 이런 수업을 할 수 있다는 것을 먼저 보여 줌 |
| 2. 왜 만들었나 | 1~2분 | 외부 AI 도구를 수업에 쓸 때의 계정·구독·로그인 문제, 결과물 겉모습만으로는 학생이 실제로 한 일을 알기 어려운 문제 |
| 3. 수업 한 사이클 요약 | 4~5분 | 아이디어 → 스튜디오 제작 → 교사의 질문 → 수정 → 개발일지 → 라운지 게시 → 교사 완료 처리. 단계마다 30초 안쪽 |
| 4. 교사가 볼 수 있는 것 | 1~2분 | 학생의 AI 대화 기록, 과제 진행 현황, 클래스별 AI 설정. 원장에게 가장 설득력 있는 부분이므로 따로 강조 |
| 5. 동기 부여 장치 | 1분 | 투자와 배지, 학생 반응. 건의함에 남은 실제 의견을 함께 보여 줌 |
| 6. 다음 단계 | 30초 | 체험 방법과 따라 하기 시리즈 안내 |

### B. 따라 하기 시리즈 (도입 후, 편당 3~8분)

**대상:** 도입을 결정한 원장과 교사. 실제 설정 순서대로 배치합니다.

| 편 | 화면 | 내용 | 기존 장 |
| --- | --- | --- | --- |
| 1 | 관리자 | 기관 개설 신청과 승인, 기관 정보와 브랜드 설정 | 13 |
| 2 | 관리자 | 교사 권한, 클래스 만들기, 클래스별 AI 수준·모드 설정 | 13, 14 |
| 3 | 관리자 | 학생 등록(기관 코드 입력, 이메일로 추가), 공개 활동명에 실명을 쓰지 않는 원칙 | 14 |
| 4 | 학생 | 과제 시작과 아이디어 기록 | 2 |
| 5 | 학생 | 스튜디오에서 제작하고 수정하기 | 3, 6 |
| 6 | 학생 | 제작 지원 기능(랭킹, 썸네일), 개발일지, 라운지 게시 | 4, 7 |
| 7 | 교사 | 과제 검토, 완료·반려·되돌리기, 보상 지급 | 9 |
| 8 | 학생·교사 | 학생이 직접 만드는 자율 과제(예: 급식 줄 대기 시간 앱) | 9 |
| 9 | 학생 | 외부 작품 등록(엔트리·스크래치·로블록스 링크, 웹 작품 파일 업로드) | 5 |
| 10 | 학생·교사 | 작품 소개 영상 만들기(화면 녹화 → 캔바 편집 → 유튜브 연결) | 8 |
| 11 | 교사 | 운영 도구: 방문 통계 읽는 법, 학생과 소통하기, 소식 기능 | 14 |

### C. 영상과 따로 관리할 자료

- **요금제:** 웹페이지나 1~2분짜리 짧은 영상으로 따로 만듭니다. 요금이나 조건이 바뀌면 이 자료만 고칩니다.
- **자주 묻는 질문:** Q&A 대화에서 나온 질문을 텍스트로 정리합니다.
  - 파이썬 파일을 올려 실행할 수 있나요?
  - 스튜디오 라이트와 플러스는 무엇이 다른가요?
  - 유료에서 무료로 바꾸면 투자와 활동 기록은 어떻게 되나요?
  - 엔트리·스크래치 작품도 올릴 수 있나요?

## 3. 새로 넣을 내용

### 아이디어가 화면 변화로 이어지는 장면

기존 영상은 AI가 학생의 의도를 그대로 구현하지 않을 수 있다는 점을 말로만 설명합니다. 재촬영에서는 다음 흐름을 한 번 실제로 보여 줍니다.

1. 학생의 의도와 다르게 나온 결과(예: 숫자가 너무 작게 보임)
2. 학생이 실행해 보며 차이를 알아차리는 장면
3. 수정을 요청하는 장면
4. 바뀐 화면
5. 바뀐 내용을 개발일지에 기록하는 장면

이 수업 방식의 핵심은 요청 문장이 아니라 이 과정입니다. 요청 문장은 짧게 지나가고, 결과 화면과 학생의 판단에 시간을 씁니다.

### 교사의 질문 카드

완성된 게임을 보고 교사가 던질 질문을 자막 카드로 띄웁니다. 교사가 캡처해 수업에 바로 쓸 수 있습니다.

- 스마트폰에서는 어떻게 조작할까?
- 숫자가 잘 보일까?
- 난이도는 어떻게 추가할까?
- 곱셈 말고 다른 연산도 적용할 수 있을까?

### 학생 수준별 차이

같은 과제를 어린 학생은 간단한 규칙으로, 높은 학년 학생은 순서도까지 그려서 진행하는 모습을 짧게 비교합니다. 여러 연령대를 가르치는 학원이 자기 수업에 대입해 보기 쉬워집니다.

### 개인정보와 안전

기존 영상에서는 13장에서 잠깐 언급하고 지나갑니다. 다음 내용을 묶어 '안심하고 쓸 수 있는 이유'로 소개 영상 앞쪽에 배치합니다. 학부모 상담 자료로도 쓸 수 있습니다.

- 공개 활동명과 프로필 주소에 실명을 쓰지 않음
- 교사가 학생의 AI 대화를 확인할 수 있음
- 클래스 단위로 AI 수준과 모드를 제한할 수 있음

### 연습용 작품 추천 목록

기존 영상 11장에서 정리해 추천하기로 한 클론 코딩 연습용 라운지 작품 목록을 실제로 만들어 소개 영상 끝이나 영상 설명란에 붙입니다.

## 4. 촬영 전 준비

- [ ] **시연용 계정 준비:** 작품 등록 한도를 해제하고 데이터를 미리 채워 둡니다. 학생 이름은 가명으로 합니다.
- [ ] **미리 만들어 둔 결과물 준비:** AI 생성 대기 시간은 편집으로 잘라내고 완성본으로 넘어갑니다. 기존 영상이 길어진 큰 원인이 대기 화면입니다.
- [ ] **알려진 문제 해결 또는 회피:** 썸네일 임시 파일 정리, 화면 반영 지연. 해결하지 못하면 해당 구간을 편집으로 정리합니다.
- [ ] **화면 기준 대본 작성:** '어디를 누르면 무엇이 바뀌는지' 단위로 대본을 씁니다. 클래스 단위 설정처럼 시연 중에 정정하는 일을 막습니다.
- [ ] **화면 설정:** 브라우저 배율 125~150%, 마우스 강조 효과 사용.
- [ ] **자막과 챕터:** 자막과 유튜브 챕터 타임스탬프를 기본으로 넣습니다.
- [ ] **시점 의존 표현 제외:** 요금, '테스트 중' 같은 표현은 본편에서 빼 영상 수명을 늘립니다.
