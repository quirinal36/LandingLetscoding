2026년 10월 12일 [수정 제안서](revision-proposal.md)에 따라 학교 대상 본문 8쪽을 제작하고, 앞뒤 표지 4쪽을 더해 총 12쪽으로 구성했다.

## 편집과 확인

- 편집 원본: `index.html`. 제목·본문·기능 설명·요금제 선택 기준은 HTML 텍스트다.
- 웹: `/ai-edu-expo`. 기존 `/brochure`와 별도 자료다.
- PDF: `../pdf/letscoding-school-brochure.pdf`. 웹 다운로드 주소는 `/ai-edu-expo/pdf`다.
- 출력: 가로 A4 총 12쪽(양면 인쇄 시 종이 6장), 짧은 쪽 넘김. 화면 최대 폭 1200px이며 모바일에서는 본문을 세로로 재배치한다.
- 원본 보관: `index-original.html`, `source-text.json`, `assets/image1.png`~`image7.png`. `source-text.json`은 PPTX 추출 기록이므로 새 문구에 맞춰 덮어쓰지 않는다. 원본의 상세 요금표 `assets/image7.png`는 별도 자료로 남겼다.

라우트는 HTML 원본과 폰트를 읽고, 제품 이미지에는 기존 `public/landing/` 자산을 사용한다. 수정 후 배포하려면 다시 빌드한다. PDF도 HTML 수정 후 재출력한다.

## 구성

1. 겉표지 — 서비스명과 이미지가 담긴 무한대 마크
2. 안쪽 앞표지 — 코딩 수업의 전환과 학교의 세 가지 도입 이점
3. 에디터 → 라운지 → 공동체의 작동 구조와 교사의 지도
4. 작품이 만들어지는 공간 - AI 활용 · AI 사용 관제·감시, 토큰 사용량 기반 요금제, AI와 함께 제작
5. 라운지 — 내 작품을 업로드하는 곳 · 작품 주소 공유와 발전, 실제 공개 작품 세 개
6. 페이퍼 네 장면과 단계별 결과물
7. 무한한 실행의 시대 — 무한대 마크와 학생의 행동에 연결한 역량
8. 창작 → 소개 → 반응 → 가상경제 참여로 이어지는 경제 활동 경험
9. 교사의 과제 제시 → 진행 확인 → 피드백, 추천 과제와 실제 개발 보고서
10. 학교 제공 환경 · 활용 기록 · 공개 범위, 유해 요청 제한
11. 안쪽 뒤표지 — 학년·학생 수·운영 기간을 중심으로 도입 문의, 요금제 보조 안내
12. 바깥 뒤표지 — 마무리 메시지, 연락처와 작품 QR

PDF는 읽는 순서대로 저장한다. 인쇄소의 접지·중철용 면배치는 포함하지 않는다.

## 검증과 재출력

```sh
node output/ai-edu-expo/check.mjs
EXPO_PLAYWRIGHT=/path/to/playwright EXPO_CHROME=/path/to/chrome node output/ai-edu-expo/export.cjs
```

서버 응답 검사: `node output/ai-edu-expo/check.mjs http://127.0.0.1:3100/ai-edu-expo`.

브라우저 검사에도 `EXPO_URL=http://127.0.0.1:3100/ai-edu-expo`를 추가하면 웹의 인쇄 버튼과 PDF 응답까지 확인한다. PDF 출력 후에는 실제 페이지 수와 렌더링을 함께 확인한다. 검증용 페이지 PNG는 시스템 임시 폴더 `ai-edu-expo-revised/`에 저장한다.

## 사용 자료와 확인 사항

### PowerPoint 핵심 내용 반영

2026년 10월 12일 원본의 세 가지 메시지를 본문 도입과 8~10쪽에 명시했다. `check.mjs`는 각 메시지의 핵심 설명이 해당 쪽에 남아 있는지 검사한다.

| 원본 PowerPoint | 반영 위치 | 유지한 내용 |
|---|---|---|
| 2~3쪽 학생별 맞춤 프로젝트와 교사 관리 | 본문 도입·9쪽 | 개별 관심사와 아이디어, 진행 상황·결과물의 한눈에 확인, 기획·AI 코딩·배포·공유의 통합 환경 |
| 4~5쪽 경제적 가치 경험 | 본문 도입·8쪽 | 작품 소개와 사용자 반응, 가상경제·배지로 참여 촉진, 창작·홍보·피드백·개선 |
| 6~7쪽 안전한 AI 활용 교육 | 본문 도입·10쪽 | 학교 제공 AI 환경과 개별 유료 구독 부담 해소, 활용 목적·방법 분석, 학생의 질문·문제 해결 과정에 대한 지도 |

- 라운지 소개 5쪽의 작품은 나나쌤 공개 작품 예시이며 학생 제작 성과로 소개하지 않는다.
- 에디터 화면은 실제 제품의 기능 검증용 시험 프로젝트다. 10쪽의 개인 프로젝트 목록은 삭제하고 AI 활용 지도 항목으로 교체했다.
- 학생별 진행 관리·AI 분석 리포트 화면은 확보되지 않아 기능 설명으로 구성했다. 9쪽은 추천 과제와 실제 개발 보고서를 예시로 사용하며, 이를 교사용 진행 관리 화면으로 소개하지 않는다. 투자 대시보드 자료는 목업임을 확인해 사용하지 않았다.
- 추천 과제 화면은 2026년 9월 자료임을 표시했다.
- 작품 QR은 `https://lounge.letscoding.kr/works`로 연결된다. 기존 도입문의 페이지에 폐기 조건이 남아 있어 학교 문의는 확인된 이메일·전화로 직접 연결했다.
- 확정되지 않은 금액·무료 체험·지원 조건은 싣지 않았다. 공개 범위와 요금제 제공 범위는 발송 전에 운영 조건과 최종 대조한다.

## 교육철학과 세 가지 축 추가

2026년 10월 12일 사용자 요청에 따라 12쪽 구성을 유지하면서 교육철학과 세 가지 축을 보강했다. 당시 구성에서는 3쪽과 8쪽에 배치했다. 현재 3쪽은 아래의 작동 구조로 대체했다.

- 3쪽: 나의 창작·공개(Papert의 constructionism), 동료의 피드백·수정(Vygotsky의 사회적 구성주의), 구경·참여·기여(Lave와 Wenger의 실천공동체), 성찰과 포트폴리오를 통한 다음 작품의 순환. 블룸 2001 개정 분류체계는 보고서·루브릭으로 학습을 살펴보는 기준으로 구분한다.
- 8쪽: 세 축을 삼각형 도식과 양방향 연결로 표현한다. 조회수에서 가상 수익과 광고·투자로, 과제의 주제에서 작품과 완료보고서로, 과제 완료에서 가상 자산으로 이어지는 관계를 설명한다. 기존 경제적 가치·배지·창작과 피드백의 내용도 유지한다.
- 근거: [교육철학 페이지](https://www.letscoding.kr/about/philosophy), [랜딩페이지의 세 가지 축](https://www.letscoding.kr/), `src/app/about/philosophy/page.tsx`, `src/components/landing/lounge-model.tsx`, `src/components/landing/loop-diagram.tsx`.
- 이론은 라운지의 교육적 설계 관점으로 설명한다. 자동 평가 기능이나 실증된 학습 효과를 추가로 주장하지 않는다.

## 표지와 도입 안내 재구성

추천한 수업 전환과 학교 도입 이점 문안을 새 2쪽에 반영하고, 교육철학 페이지를 3쪽으로 옮겼다. 이전 10쪽 도입 안내와 11쪽 수업 준비는 현재 11쪽에 통합했다. 총 12쪽을 유지하며 학생·운영·프로젝트·이용 조건, Lite/Plus/Pro 5x 선택 기준, 학교 연락처와 작품 QR을 함께 안내한다.

## 3쪽 작동 구조

2026년 10월 12일 2쪽의 수업 전환에서 이어지는 작동 원리를 보여주도록 3쪽을 교체했다. 실제 에디터·공개 작품 목록·빌리지 장면과 함께 에디터 → 라운지 → 공동체를 연결하고, 배포·공유와 댓글·가상 투자, 반응을 반영한 작품 개선을 표시한다. 세 카드를 페이지의 중심으로 확대하고, 카드마다 학생의 활동과 교사의 지도 역할을 짝지어 설명한다. 상단 문구는 한 줄로 줄여 2쪽의 강점이 실제 수업 적용으로 이어지게 한다. 6쪽은 학생의 경험과 결과물 설명을 유지한다.

## 카드 이미지와 꼬리말

3쪽은 세로 카드 전체에 실제 화면을 크롭해 채우고, 하단 그라데이션 위에 공간 이름·학생 활동·교사 역할을 배치한다. 가로 원본의 일부가 잘리는 대신 핵심 장면이 크게 보이도록 이미지 위치를 조정했다. 12쪽 전체 꼬리말은 “AI 활용 프로젝트 수업을 위한 교육”으로 통일했다.

## 에디터와 라운지 상세 소개 순서

3쪽의 전체 구조 다음에 에디터(4쪽) → 라운지(5쪽) → 학생의 경험(6쪽) → 배움의 방향(7쪽)을 배치한다. 이전 7쪽을 4쪽으로, 이전 4쪽을 5쪽으로, 이전 5쪽을 7쪽으로 옮겼다. 4·5쪽 제목과 서비스 주소를 갱신하고 6쪽 본문은 유지했다. 페이지 ID·제목 ID·꼬리말·본문 장 번호를 함께 정리했으며 총 12쪽이다.

## 8~12쪽 도입 결정 흐름 정리

2026년 10월 13일 경제 활동(8쪽) → 교사의 수업 운영(9쪽) → AI 활용 지도(10쪽) → 도입 문의(11쪽) → 뒤표지 연락처(12쪽)의 역할을 구분했다. 8쪽의 과제관리 설명은 9쪽에 통합하고, 10쪽은 학교 제공 환경·활용 기록·공개 범위로 정리했다. 11쪽은 학년·학생 수·운영 기간과 연락처를 강조하며 요금제는 보조 정보로 배치했다. 1~7쪽과 12쪽 본문은 유지했다.

9쪽의 개발 보고서 이미지는 중앙 라운지 저장소 `docs/assets/partner-speech-deck/07-project-report.png`에서 가져와 `public/landing/project-report.png`로 저장했다. 실제 ‘약수 미로’ 보고서에서 주제를 선택한 이유를 적은 부분을 보여준다. 과제관리나 AI 분석 화면으로 소개하지 않는다.

## 에디터 페이지 핵심 강조

2026년 10월 13일 4쪽을 AI 사용 관제·감시, AI 모델 토큰 사용량 기반 요금제, AI와 함께 제작의 세 항목으로 정리했다. 앞의 두 항목을 강조하고 사진 아래 캡션·기존 번호 핀·남색 과정 요약 박스를 제거했다. 실시간 감시나 구체적인 요율·추가 과금 조건은 별도로 주장하지 않는다.

4쪽 제목을 “작품이 만들어지는 공간 - AI 활용” 한 줄로 바꾸고, 확보한 높이를 활용해 화면 영역을 확대하고 설명 글자와 카드 여백을 키웠다.

5쪽 제목을 “내 작품을 업로드하는 곳”으로 바꾸고, 부제를 작품 주소 생성과 친구·가족에게 공유하는 두 줄로 정리했다. 송편 가게 위 설명은 홍보와 판매 경험, 이미지 편집기 위 설명은 공감능력 향상으로 변경했다. 작품 출처와 루캣 안내 캡션은 화면과 PDF에서 숨겼으며 원문은 HTML에 보존했다.

앞표지(1쪽)와 뒤표지(12쪽)를 제외한 2~11쪽의 텍스트를 역할별 공통 규칙으로 정리했다. 인쇄용 HTML 기준 페이지 제목은 43px·700·행간 1.24·파랑(#4879d1), 카드 제목은 23px·700·행간 1.4, 부제는 19px·400, 본문은 18px·400·행간 1.6, 캡션은 13px·400이다. 아이브로우는 14px·700, 단계·보조 라벨은 13px·700, 연락처는 23px·700으로 맞췄다. 앞표지와 뒤표지는 기존의 큰 제목, 흰색·금색 강조, 부제 크기와 배치를 유지한다.

2쪽 On·Off는 핵심 시각 요소로 큰 크기를 유지하며 굵기를 800으로 맞췄다. 3쪽 사진 위 공간 이름과 핵심 수치·항목은 32px·700으로 통일했다. 배경색과 이미지 구성은 유지하고, 작은 화면에서도 공통 크기 규칙이 함께 바뀐다.
